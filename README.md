# aialib — AI-Aware Threat Library

[![License: Apache 2.0](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](LICENSE)
[![Python 3.11+](https://img.shields.io/badge/python-3.11%2B-blue.svg)](https://www.python.org/downloads/)
[![Reproducible](https://img.shields.io/badge/reproducible-seed%201337-success.svg)](docs/repro_checklist.md)

A reproducible pipeline and dataset for studying *why* code generated by Large
Language Models is vulnerable. `aialib` expands templated security prompts,
runs them through one or more LLM providers, scans every completion with a
multi-detector ensemble (Bandit + Semgrep + AI-aware heuristics), and exports
an annotated **threat library** that links each finding to:

- a CWE class and OWASP Top-10 tag,
- an **AI cause** label (`unsafe_default`, `hallucinated_dependency`,
  `prompt_overgeneralization`, `context_misalignment`, `template_reuse`),
- a **propagation vector** (`database_query`, `filesystem`, `network`, ...),
- a **human–AI factor** (`blind_trust`, `knowledge_gap`, `time_pressure`, ...),
- one or more **MITRE ATLAS** techniques.

The current public release ships **729 annotated findings** mined from
**2,144 generated samples** across four LLM providers (OpenAI `gpt-4o-mini`
and `gpt-4.1`, Anthropic `claude-sonnet-4`, MBZUAI-IFM `K2-Think v2`) and
exports them in CSV, SQLite, and SARIF for direct CI/CD integration.

This artifact accompanies the master's thesis *"Why AI-Generated Code Is
Vulnerable: Cause Taxonomy, Threat Mapping, and CI/CD Security Controls"*
(MBZUAI, 2026).

## Try it in 60 seconds

The pipeline runs **fully offline** by default — no API keys, no network. Three
options:

**Docker (one command):**
​```bash
docker run --rm -v "$PWD/out:/app/out" ghcr.io/aljaberi500/aialib:0.1.0
# → out/threat_library.csv, out/threat_library.sqlite, out/threat_library.sarif
​```

**Local make:**
```bash
python3.11 -m venv .venv && source .venv/bin/activate
make setup
make run
```

**One-off snippet (no full corpus run):**
```bash
python -m aialib.pipeline.process_snippet \
  --code examples/sql_injection.py \
  --prompt-text "Look up a user by username"
# → out/manual_run/threat_library.csv
```

A pre-built sample of every export format is committed under
[`sample_outputs/`](sample_outputs/) so reviewers can inspect the schema
without running anything.

## What problem does this solve?

Existing benchmarks measure *how often* LLM-generated code is vulnerable.
They do not explain **why**, **how the same flaw propagates** across refactors
and reuse, or **how findings map to AI-specific threat models**. `aialib`
fills that gap by:

1. Generating code under controlled, reproducible conditions (fixed seed,
   provider-pinned generation parameters, prompt-level provenance).
2. Detecting both classical CWEs (Bandit/Semgrep) and AI-specific risks
   (dependency hallucination, unsafe defaults like `debug=True` /
   `verify=False`, multi-file sanitization bypasses).
3. Annotating every finding with a *cause* and *propagation* label, plus a
   curated CWE → MITRE ATLAS crosswalk.
4. Emitting CI/CD-ready outputs (SARIF for IDEs and PR checks; SQLite for
   tool integrations; CSV for analysts and notebooks).

## Pipeline at a glance

```
data/prompts_v2.yaml
        │      ┌────────────────────────────┐
        ▼      ▼                            │
  expand → generate → scan → annotate → validate → export
                  ▲                                  │
                  └────────────── Bandit / Semgrep / AI risks
                                                     ▼
                              out/threat_library.{csv,sqlite,sarif}
                              reports/{coverage,novelty,propagation}.json
```

Every stage is independently invocable as a Python module
(`python -m aialib.<stage>...`) and as a Make target (`make expand|generate|
scan|annotate|validate|export|run`). See [`docs/codebase-overview.md`](docs/codebase-overview.md)
for module-level details and [`docs/repro_checklist.md`](docs/repro_checklist.md)
for the reproducibility checklist (seeds, manifests, config hashes).

## Threat library schema (excerpt)

```csv
vuln_id,language,generator,prompt_id,cwe_id,owasp_tag,severity,sink_api,
ai_cause[],propagation_vector[],human_ai_factor[],atlas_techniques[],
detection_tools[],validation_level,mitigation_short,evidence_ref
```

Every record carries a normalized token hash and an AST hash, enabling
duplicate detection and *novelty* clustering by `(CWE, sink API,
normalized hash)`. The full JSON Schema is in
[`schemas/threat_entry.schema.json`](schemas/threat_entry.schema.json).

## Reproducibility

- Deterministic prompt expansion: byte-identical output for a fixed seed
  (verified by `tests/test_expand_deterministic.py`).
- `data/run_manifest.json` records seed, commit SHA, analyzer versions,
  ruleset hashes, and pipeline version.
- Provider parameters logged alongside completions
  (temperature, top-p, max-tokens, system prompt, model).
- Validation gate enforces JSON Schema compliance, mapping coverage,
  ATLAS catalog membership, and severity vocabulary; reports under
  `sample_outputs/reports/`.

See [`docs/repro_checklist.md`](docs/repro_checklist.md).
